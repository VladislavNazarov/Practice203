# Стратегия контейнеризации

## 1. Выбор базового образа

Для контейнеризации выбран образ `python:3.13-slim`.

Причины выбора:

- образ значительно меньше полноценного `python:3.13`, что уменьшает итоговый размер Docker-образа;
- базируется на Debian, что обеспечивает хорошую совместимость Python-пакетов и упрощает отладку;
- slim-образ содержит только минимально необходимый runtime без лишних утилит;
- образ хорошо подходит для production-контейнеров и CI/CD окружений.

Для управления зависимостями используется менеджер пакетов `uv`.

Преимущества `uv`:

- значительно быстрее установки зависимостей по сравнению с `pip`;
- поддержка lock-файла (`uv.lock`) для воспроизводимых сборок;
- оптимизированная работа с Docker cache.

В `Dockerfile` применяется подход **multi-stage build**:

- `builder` stage устанавливает зависимости проекта на основе `pyproject.toml` и `uv.lock`;
- `runtime` stage получает уже готовое окружение и исходный код приложения, исключая лишние build-зависимости.

Это позволяет уменьшить размер финального образа и повысить безопасность контейнера.

## 2. Управление ENV

Для настройки контейнеров используются переменные окружения.

| Переменная | Назначение | Пример значения |
| --- | --- | --- |
| `POSTGRES_DB` | имя базы данных PostgreSQL | `app_db` |
| `POSTGRES_USER` | пользователь базы данных | `postgres` |
| `POSTGRES_PASSWORD` | пароль пользователя БД | `postgres` |
| `DATABASE_URL` | строка подключения приложения к PostgreSQL | `postgresql://postgres:postgres@postgres:5432/app_db` |
| `REDIS_HOST` | адрес Redis внутри Docker сети | `redis` |
| `REDIS_PORT` | порт Redis | `6379` |
| `PYTHONUNBUFFERED` | отключение буферизации вывода Python | `1` |
| `UV_COMPILE_BYTECODE` | компиляция Python-файлов в `.pyc` | `1` |
| `UV_LINK_MODE` | способ установки зависимостей uv | `copy` |

Основной принцип:

- конфигурация вынесена в переменные окружения;
- код приложения не содержит жестко заданных параметров;
- одинаковая конфигурация может использоваться в локальной среде, CI и production.

## 3. Оптимизация образа

В Dockerfile применены следующие оптимизации:

- используется **multi-stage build**, разделяющий этап установки зависимостей и runtime окружение;
- зависимости устанавливаются до копирования кода приложения, что позволяет эффективно использовать Docker cache;
- используется lock-файл `uv.lock`, обеспечивающий воспроизводимость окружения;
- применяется минимальный базовый образ `python:3.13-slim`;
- используется кэш зависимостей `uv` при сборке контейнера.

Пример оптимизации слоев:

1. копирование `pyproject.toml` и `uv.lock`
2. установка зависимостей
3. копирование исходного кода приложения

Это позволяет избежать повторной установки зависимостей при изменении кода.

### Сравнение размера образа

До оптимизации:

- одностадийный Dockerfile
- установка зависимостей через `pip`
- полный образ `python`

После оптимизации:

- multi-stage build
- менеджер зависимостей `uv`
- базовый образ `python:3.13-slim`

Ожидаемое уменьшение размера образа — примерно на **40–60%**.

## 4. Вывод

Контейнеризация обеспечивает воспроизводимость среды разработки и запуска приложения.

Основные преимущества:

- приложение собирается одинаково на любой машине;
- инфраструктура (`app`, `postgres`, `redis`) описана декларативно через Docker Compose;
- зависимости фиксированы в `uv.lock`;
- контейнеры взаимодействуют через внутреннюю Docker-сеть;
- данные PostgreSQL сохраняются в persistent volume.

Это позволяет быстро разворачивать приложение в локальной среде, CI или на любом сервере.
