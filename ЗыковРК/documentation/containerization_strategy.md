# Стратегия контейнеризации

## 1. Выбор базовых образов

### Для приложения (C# ASP.NET Core)
- **Базовый образ для сборки:** `mcr.microsoft.com/dotnet/sdk:9.0`  
  Официальный образ от Microsoft, содержащий .NET SDK. Необходим для компиляции и публикации приложения. Используется только на этапе сборки (build stage).
- **Базовый образ для выполнения:** `mcr.microsoft.com/dotnet/aspnet:9.0`  
  Минимальный образ, содержащий только .NET Runtime и ASP.NET Core. Выбран для финального контейнера, чтобы:
  - Уменьшить размер образа (не включает компиляторы, исходники и т.п.);
  - Снизить поверхность атаки (меньше установленных пакетов);
  - Соответствовать рекомендациям Microsoft по запуску ASP.NET Core в контейнерах.

### Для базы данных и кэша
- **PostgreSQL:** `postgres:15-alpine`  
  Компактный образ на основе Alpine Linux, официальный, с встроенными проверками здоровья.
- **Redis:** `redis:7-alpine`  
  Аналогично, минимальный образ для кэширования.

## 2. Переменные окружения (ENV)

| Переменная | Назначение | Пример значения в `docker-compose.yml` |
|------------|------------|-----------------------------------------|
| `ASPNETCORE_ENVIRONMENT` | Режим запуска ASP.NET Core | `Development` |
| `ConnectionStrings__DefaultConnection` | Строка подключения к PostgreSQL | `Host=db;Port=5432;Database=vrkayak;Username=postgres;Password=postgres` |
| `Redis__ConnectionString` | Адрес Redis | `cache:6379` |

Все чувствительные данные (пароли) задаются через переменные окружения и могут быть переопределены в production-среде.

## 3. Оптимизация образа (Multi‑stage build)

Применена многоступенчатая сборка, разделяющая этапы компиляции и выполнения:

- **Stage 1 (build):**  
  - Копируется только `.csproj` и восстанавливаются зависимости (кэшируется).
  - Копируется весь исходный код и выполняется `dotnet publish`.
- **Stage 2 (runtime):**  
  - Используется чистый образ `aspnet:9.0`.
  - Копируются только опубликованные файлы из первого этапа.
  - Задаются переменные окружения и точка входа.

**Результат:**
- Итоговый образ содержит только необходимые для работы артефакты.
- Размер образа уменьшен с ~700 МБ (если бы использовался SDK) до **~200 МБ**.
- Ускорение повторных сборок за счёт кэширования слоя с зависимостями.

## 4. Выводы
Контейнеризация обеспечивает идентичность окружений разработки, тестирования и эксплуатации, а также упрощает развёртывание приложения.
