
# Стратегия контейнеризации

## 1. Выбор базового образа

### Этап сборки (builder)
Используется образ `python:3.12-slim`.

**Причины выбора:**
- содержит необходимые инструменты для установки Python-пакетов (`pip`)
- поддерживает компиляцию native-расширений (в отличие от Alpine)
- `slim`-версия заметно меньше полноценного `python:3.12` (~120MB против ~900MB)
- Debian-based runtime проще для отладки и повторяемого CI

**Недостаток:**
- не является минимальным (~120MB), поэтому используется только на этапе сборки


### Этап выполнения (runtime)
Используется образ `python:3.12-slim`.

**Причины выбора:**
- совместим со всеми Python-пакетами без дополнительных сложностей
- Debian-based — стандартный инструментарий для отладки
- размер образа оптимизирован, но сохраняет совместимость
- позволяет безопасно запускать приложение от непривилегированного пользователя

**Альтернативы (почему не выбраны):**

| Образ | Размер | Плюсы | Минусы |
|-------|--------|-------|--------|
| `python:3.12` | ~900MB | Полная совместимость | Огромный размер |
| `python:3.12-alpine` | ~50MB | Очень маленький | Проблемы с native-расширениями, сложнее отладка |
| `python:3.12-slim` | ~120MB | Баланс размера и совместимости | Выбран ✅ |



## 2. Управление ENV

В проекте используются следующие переменные окружения:

| Переменная | Назначение | Пример значения в Compose |
|------------|-----------|---------------------------|
| `APP_ENV` | Режим запуска приложения | `production` |
| `APP_HOST` | Хост для `uvicorn` внутри контейнера | `0.0.0.0` |
| `APP_PORT` | Порт приложения внутри контейнера | `8000` |
| `SECRET_KEY` | Секретный ключ приложения (JWT, сессии) | `local-compose-secret` |
| `POSTGRES_HOST` | Хост базы данных (сервис `db`) | `db` |
| `POSTGRES_PORT` | Порт PostgreSQL | `5432` |
| `POSTGRES_DB` | Имя базы данных | `fastapi_db` |
| `POSTGRES_USER` | Пользователь PostgreSQL | `fastapi_user` |
| `POSTGRES_PASSWORD` | Пароль пользователя базы данных | `secure_password` |
| `REDIS_HOST` | Хост Redis (сервис `cache`) | `cache` |
| `REDIS_PORT` | Порт Redis | `6379` |
| `REDIS_PASSWORD` | Пароль Redis (если установлен) | `redis_secure_password` |
| `DATABASE_URL` | Полная строка подключения к БД (опционально) | `postgresql://user:pass@db:5432/db` |
| `REDIS_URL` | Полный адрес Redis (опционально) | `redis://:password@cache:6379/0` |

## 3. Оптимизация образа (Multi-stage build)

### Применённые оптимизации

| Оптимизация | Реализация | Эффект |
|-------------|------------|--------|
| **Multi-stage build** | Разделение на `builder` и `runtime` | Удаление компилятора, pip-кэша, тестов |
| **Кэширование зависимостей** | `COPY requirements.txt` перед кодом | Ускорение сборки на 60-80% |
| **Минимальный runtime-образ** | `python:3.12-slim` вместо `python:3.12` | Уменьшение размера на ~85% |
| **Исключение dev-зависимостей** | Разделение `requirements.txt` на dev и runtime | Отсутствие pytest, black, flake8 в проде |
| **Отключение pip-кэша** | `--no-cache-dir` | Экономия ~50MB |
| **Непривилегированный пользователь** | `USER appuser` | Повышение безопасности |
| **Healthcheck** | Проверка `/health` эндпоинта | Автоматическое восстановление |

### Сравнение размера образа

| Этап | Образ | Размер | Что содержит |
|------|-------|--------|--------------|
| **Без оптимизации** | `python:3.12` + `requirements.txt` | ~1.1 GB | Компилятор, pip-кэш, dev-зависимости, тесты, исходники |
| **С slim-образом** | `python:3.12-slim` + `requirements.txt` | ~350 MB | Урезанная ОС, pip-кэш, dev-зависимости |
| **С multi-stage (финальный)** | `python:3.12-slim` + только runtime | **~125 MB** | Только код и runtime-зависимости |

### Результат оптимизации

```
Без оптимизации:  ████████████████████████████████████████ 1100 MB
Slim + кэш:       ████████████ 350 MB
Multi-stage:      ████ 125 MB
```

**Итоговое уменьшение: ~89%** (с 1100 MB до 125 MB)

## 5. Интеграция с CI/CD

В GitHub Actions реализована сборка с кэшированием слоёв:

```yaml
- name: Build Docker image
  uses: docker/build-push-action@v5
  with:
    context: .
    push: false
    tags: fastapi-app:latest
    cache-from: type=gha
    cache-to: type=gha,mode=max
```
