# Containerization Strategy

## 1. Выбор базового образа

### Этап сборки (builder)
Используется образ `golang:1.25`.

Причины выбора:
- содержит полный набор инструментов для сборки Go-приложения
- поддерживает работу с зависимостями (`go mod`)
- упрощает процесс компиляции бинарного файла

Недостаток:
- большой размер (~800MB), поэтому используется только на этапе сборки

---

### Этап выполнения (runtime)
Используется образ `alpine:3.19`.

Причины выбора:
- минимальный размер (~7MB)
- сниженная поверхность атаки → выше безопасность
- подходит для запуска статически скомпилированного Go-бинарника

Дополнительно:
- создаётся пользователь `appuser`
- контейнер запускается не от root → повышенная безопасность

---

## 2. Управление переменными окружения (ENV)

В проекте используются следующие переменные окружения:

| Переменная   | Назначение |
|-------------|-----------|
| DB_HOST     | Хост базы данных (сервис `db`) |
| DB_PORT     | Порт PostgreSQL (5432) |
| DB_NAME     | Имя базы данных |
| DB_USER     | Пользователь базы данных |
| DB_PASSWORD | Пароль пользователя базы данных |
| REDIS_HOST  | Хост Redis (сервис `cache`) |
| REDIS_PORT  | Порт Redis (6379) |

Особенности:
- задаются в `docker-compose.yml`
- позволяют менять конфигурацию без изменения кода
- используются для подключения к базе данных и Redis

---

## 3. Оптимизация образа (Multi-stage build)

### До применения multi-stage
При использовании только `golang:1.25`:
- размер образа: ~800MB
- содержит компилятор, исходный код и кэш зависимостей

Недостатки:
- большой размер
- медленная загрузка
- повышенные риски безопасности

---

### После применения multi-stage
Финальный образ (`alpine:3.19`):
- размер: ~15–25MB
- содержит только скомпилированный бинарный файл и минимальное окружение

---

### Результат
- уменьшение размера: ~95%
- ускорение деплоя
- снижение количества уязвимостей
- соответствие best practices Docker

---

## 4. Дополнительные оптимизации

В Dockerfile реализованы:
- разделение стадий сборки и выполнения
- кэширование зависимостей (`go mod download`)
- статическая сборка (`CGO_ENABLED=0`)
- запуск от непривилегированного пользователя
- использование минимального runtime-образа

---

## 5. Вывод

Применение multi-stage сборки и лёгкого runtime-образа позволило:
- уменьшить размер контейнера
- повысить безопасность
- ускорить развертывание приложения
