# Стратегия контейнеризации проекта "Эпштейн интернет-магазин"

## Выбор базовых образов

| Сервис | Базовый образ | Размер | Обоснование |
|--------|---------------|--------|-------------|
| **App** | `python:3.11-slim` | ~120 MB | Минимальный образ Python, содержит только необходимое для runtime |
| **DB** | `postgres:15-alpine` | ~80 MB | Alpine Linux — максимально легковесный, безопасный |
| **Cache** | `redis:7-alpine` | ~30 MB | Минимальный образ Redis на Alpine |

## Многоэтапная сборка (Multi-stage build)

Dockerfile разделён на два этапа:

1. **builder** — установка зависимостей, компиляция (если нужна)
2. **runtime** — только исполняемые файлы и код

### Сравнение размера образа

| Вариант | Размер | Причина |
|---------|--------|---------|
| Без multi-stage | ~800 MB | Включены компиляторы (gcc), системные библиотеки, кэш pip |
| С multi-stage | ~150 MB | Только зависимости runtime, без инструментов сборки |

## Управление переменными окружения

| Переменная | Назначение | Пример |
|------------|------------|--------|
| `POSTGRES_USER` | Пользователь БД | postgres |
| `POSTGRES_PASSWORD` | Пароль БД | secret |
| `POSTGRES_DB` | Имя базы данных | shop |
| `DATABASE_URL` | Полная строка подключения | postgresql+asyncpg://postgres:secret@db:5432/shop |
| `REDIS_URL` | Строка подключения к Redis | redis://cache:6379/0 |

## Безопасность

- Использование непривилегированного пользователя в контейнере
- Отсутствие компиляторов и инструментов сборки в финальном образе
- Пароли передаются через переменные окружения
- Использование `.dockerignore` для исключения лишних файлов
